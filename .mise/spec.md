# Spec: Node 24 throughout

## What

Make Node 24 the single supported Node version line for betterbe:

- The published `engines.node` constraint becomes `>=24` (was `>=20`). This is a breaking change for Node 20/22 consumers and ships as a major release.
- `@types/node` is pinned to the Node 24 line (`^24`) instead of `^26`, so type definitions match the runtime.
- Dependabot stops proposing `@types/node` semver-major updates, so the types stay on 24.
- CI workflows already use `node-version: 24` and stay unchanged. No version pin file (`.nvmrc`, `.node-version`, etc.) is added.
- No README or other doc names a supported Node version (checked: `README.md`, `CLAUDE.md`, `.cursor`, `.github`), so no doc changes.

## Design

- `package.json`: `"engines": { "node": ">=24" }`; `devDependencies["@types/node"]` set to `^24` (resolves to latest 24.x, e.g. 24.19.1).
- `yarn.lock`: regenerated by `yarn install` (or `yarn up @types/node@^24`) so the `@types/node@npm:^24...` entry replaces the `^26.6.4` entry. Peer ranges in vite (`^20.19.0 || >=22.12.0`) and vitest (`^22.0.0 || >=24.0.0`) accept 24.x.
- `.github/dependabot.yml`: add to the `npm` update entry
  ```yaml
  ignore:
    - dependency-name: '@types/node'
      update-types: ['version-update:semver-major']
  ```
- `@types/node` is consumed only by `tsconfig.eslint.json` (`"types": ["node"]`) for `eslint.config.mjs`; `src/` uses no Node APIs, so build output does not change.
- Release mechanics (handled at PR time, not in a task): PR title `feat: ...` (no `type!:` shorthand); the PR description's last paragraph is a `BREAKING CHANGE: Node.js 24 or later is now required (engines.node >=24).` footer with nothing after it.
- Nothing is removed beyond the old version ranges.

## Hard-to-undo

- Public API change: `package.json` `engines.node` raised from `>=20` to `>=24`, breaking Node 20/22 consumers. Once merged to `main`, `.github/workflows/publish.yml` publishes a major release to npm automatically, which cannot be undone. The PR description must end with a `BREAKING CHANGE:` footer as its last paragraph.
