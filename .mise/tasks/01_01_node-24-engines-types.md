# 01_01 Node 24 engines and types

## Goal

Make the package require and target Node 24: raise `engines.node` to `>=24`, pin `@types/node` to the Node 24 line, and stop Dependabot from proposing `@types/node` major upgrades.

## Files to modify/create

- `package.json`
- `yarn.lock` (regenerated by yarn, not hand-edited)
- `.github/dependabot.yml`

## Background

- betterbe is a dependency-free TypeScript validation library published to npm. Yarn 4.12.0 (`packageManager`, `.yarnrc.yml` with `nodeLinker: node-modules`).
- `package.json:14-16` has `"engines": { "node": ">=20" }`, the only published Node constraint.
- `package.json:31` has `"@types/node": "^26.6.4"`; `yarn.lock:353-360` holds the matching `@types/node@npm:^26.6.4` entry and `yarn.lock:581` the workspace dependency line. `@types/node@24` latest is 24.19.1.
- `@types/node` is used only by `tsconfig.eslint.json:6` (`"types": ["node"]`, for `eslint.config.mjs`). `src/` uses no Node APIs.
- `.github/dependabot.yml:7-23` has one `npm` update entry with `groups` and no `ignore`.
- CI workflows (`.github/workflows/publish.yml:26`, `.github/workflows/dependabot.yml:30`) already use `node-version: 24`; do not touch them.
- Design decisions: no `.nvmrc`/`.node-version`/`volta` pin file; no README/doc mentions a Node version, so no doc edits. The engines bump is a breaking change released as a major via a `BREAKING CHANGE:` PR footer, which is handled at PR time, not in this task.

## Guides

None.

## Implementation details

1. In `package.json`, change `"node": ">=20"` to `"node": ">=24"`.
2. Run `yarn up @types/node@^24` from `/Users/eric/Code/betterbe`. Yarn 4.12.0 writes `"@types/node": "^24"` to `package.json` and a `yarn.lock` entry keyed `"@types/node@npm:^24"` resolving to the latest 24.x (24.19.1 at planning time). Accept the `^24` range exactly as yarn writes it. Confirm `package.json` shows `"^24"` and `yarn.lock` has no `@types/node@npm:^26` entry left.
3. In `.github/dependabot.yml`, add under the `npm` entry (sibling of `schedule` and `groups`, same indentation):
   ```yaml
   ignore:
     - dependency-name: '@types/node'
       update-types: ['version-update:semver-major']
   ```
   Keep single-quoted strings to match the file's style.

## Gotchas

- Do not hand-edit the `@types/node` range in `package.json` after `yarn up` (e.g. to `^24.19.1`). The range must match the `yarn.lock` key (`@types/node@npm:^24`), or CI's immutable `yarn install` fails.
- `tsconfig.json` has `skipLibCheck: false`; `yarn lint` type-checks `eslint.config.mjs` with `@types/node`, so lint must pass with the 24 types.
- `yarn prettier --check .` covers `.github/dependabot.yml` and `package.json`; run `yarn prettier --write` on edited files if needed.
- Do not edit `version` in `package.json`; the release workflow bumps it.
